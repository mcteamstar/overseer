# overseer

Content moderation agent for [Blank White Cards](https://blankwhite.cards) — an R18+ party card game where players submit their own cards.

Built with [Strands Decider 2B](https://strandsagents.com/blog/introducing-strands-decider/) as the policy decision engine, deployed on [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/).

---

## Why a decision model, not a frontier LLM

Frontier LLMs trip guardrails on exactly the content you're trying to moderate. Strands Decider reads harmful content as `state`, answers a typed choice question, and returns a probability — no token generation, no guardrail trigger path:

```json
{ "state": "[card content]", "questions": { "harm": { ... } } }
→ { "answers": { "harm": { "probabilities": { "hide": 0.82, "ok": 0.18 } } } }
```

See [`docs/submission.md`](docs/submission.md) for the full write-up.

---

## Pipeline

Four stages, cheapest first. Most cards never reach the model.

```
Stage 1: Deny-list     ~0ms    Human-authored hard blocks (O(1) Set lookup)
Stage 2: Spam filter   ~0ms    Gibberish, empty, and identical title/description
Stage 3: Decider 2B   ~935ms   Combined no-value + harm in one POST
Stage 4: Nova Lite    ~800ms   Fallback LLM for ambiguous edge cases
```

Stages 1–2 exit immediately. Stage 4 only runs on cards that passed Decider — cards that are by definition less likely to trip LLM guardrails.

## Running locally

### 1. Start the Decider endpoint

```bash
pip install uv
uv pip install strands-decider==0.1.0

# Weights: amazon/strands-decider-2B-qwen3.5-v1-2610 (LoRA) + Qwen/Qwen3.5-2B-Base
strands-decider serve ./strands-decider-2B-qwen3.5-v1-2610 \
  --base-model ./Qwen3.5-2B-Base \
  --device mps \
  --host 127.0.0.1 \
  --port 8000
```

### 2. Run the agent

```bash
cd app
npm install
npm run build       # → dist/main.js

PORT=8090 \
DECIDER_URL=http://localhost:8000 \
node dist/main.js
```

### 3. Invoke

```bash
curl http://localhost:8090/invocations \
  -H "Content-Type: application/json" \
  -H "x-amzn-bedrock-agentcore-runtime-session-id: test-1" \
  -d '{
    "items": [
      {"id": "1", "fields": {"title": "Drink bitch", "description": "Make someone drink"}},
      {"id": "2", "fields": {"title": "test", "description": "test"}}
    ]
  }'
```

## Customising for your use case

The criteria in `app/moderation.config.yaml` are tuned for BWC's content policy. To adapt:

1. **Rewrite the questions** in `app/moderation.config.yaml`. Use concrete examples, not abstract rules — the model pattern-matches better on specifics. See [`evaluators/PROMPT_EXPERIMENTS.md`](evaluators/PROMPT_EXPERIMENTS.md) for findings.

2. **Test your criteria against the probe set:**
   ```bash
   cd evaluators && pip install httpx
   DECIDER_URL=http://localhost:8000 python -m evaluators probe
   ```
   Edit `evaluators/criteria.py` and re-run until hide recall and ok specificity are acceptable.

3. **Build a labelled dataset:**
   ```bash
   python -m evaluators fetch
   # Add "expected": "hide"|"ok" and "reason": "..." to a sample of dataset-full.json
   # Save as evaluators/dataset.json
   ```

4. **Find your thresholds:**
   ```bash
   AGENT_URL=http://localhost:8090/invocations python -m evaluators eval
   python -m evaluators eval --split all --threshold 0.40
   ```

5. **Score the full deck:**
   ```bash
   python -m evaluators fulldeck
   python -m evaluators fulldeck --resume   # if interrupted
   ```

Results are saved to `evaluators/results/`.
